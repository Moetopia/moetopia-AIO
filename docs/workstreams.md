## 修改范围

- 当前对话负责 `packages/ui`、`packages/locales`、`packages/portal`、各应用 `app` 目录及前端测试。可复用视觉直接进入 UI 库，完整规则见 [前端规范](frontend.md#可复用界面的归属)。
- 后端对话建议负责 `apps/api`、协议实现、持久化、迁移和后台任务；按现有架构推进，不重新开一套身份或会话实现。
- `packages/api-client` 的 OpenAPI 及生成类型由后端契约变更驱动生成，前端消费，不手改生成文件。协议端点与业务 API 分别遵循 [API 契约](api-contracts.md) 和 [身份安全](identity-security.md)。
- 接口、共享配置、依赖清单及共同规范属于交接点。同一时刻由一个对话修改具体文件，另一个对话先读取现状；不要让两个会话同时重写契约或格式化同一批文件。接口变化记录路径、字段语义、错误与兼容影响，随后由前端适配。
- 当前工作区没有 Git 元数据，不能假定聊天分支等于代码隔离。先按文件范围避免并发覆盖；不要自行初始化 Git 或为隔离而 reset/clean/stash。也不要让两个会话同时启动或停止同一套开发进程。

## 后端对话起始说明

可向新对话发送：

> 这个对话负责 Moetopia 后端，另一个现有对话负责前端/UI。先阅读 AGENTS.md、README、docs/implementation-status.md、docs/workstreams.md 和相关 ADR，再检查当前实现。继续既有 Go 模块化单体、Ent、Fosite 与 Go 服务端会话方案，不改前端样式或重复搭建工程。优先推进完整 OAuth/OIDC 与账号缺失能力；业务接口改变时同步 OpenAPI、生成类型和契约文档，并明确哪些已验证、哪些仍未实现。不要把开发者/管理员页面壳当作业务已完成；不要操作同机其他项目资源。

不在交接消息中附密码、私钥、验证码、邀请码或完整数据库连接串。运行环境细节查 [开发环境](development.md) 与 [工程指南](run-foundation.md)。
