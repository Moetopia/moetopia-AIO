# Moetopia 设计系统

状态：Headless + Storybook、中英双语、明暗主题和二次元方向已明确。完成基础组件与看板娘配色评审后，用户已要求进入页面设计；先前未通过的页面不作为既定布局。组件参考 KunUI，页面组织参考 nextmoe，并沿用薄荷绿、雾蓝和深蓝灰角色配色。Reka/Tailwind 已用于开发实现，具体页面效果仍需评审。历史比较见 [ADR-0003](decisions/0003-headless-design-system.md)，当前基线见 [ADR-0013](decisions/0013-implementation-baseline.md)。

## 品牌与参考边界

2026-10-18 最新范围：用户已授权开始页面设计，将当前组件与品牌配色接入 account/admin/developer。以 [KunUI](https://ui.kungal.com/components/button) 的统一颜色、变体和尺寸组织方式为组件参考，借鉴 nextmoe 的认证页和工作区组织；不直接替换为 KunUI 依赖，也不复制其品牌、角色和业务规则。此前页面迭代没有通过用户视觉评审，不能作为已确认布局继续扩展。可复用界面必须进入 UI 库，具体归属由 [前端规范](frontend.md#可复用界面的归属) 定义。

组件视觉继续参考 KunUI 的细边框、纯色表面、12px 控件圆角、16px 面板圆角和交互层级。2026-10-18 用户提供薄荷绿 C++ 发夹少女立绘，要求颜色和风格贴近该角色，当前主色方向据此从鲜明蓝色调整为薄荷绿与雾蓝灰；具体配色仍是可评审实现，不把用户提供参考图等同于所有设计细节已定稿。实际组件 API、当前组件清单、参考文件、组合方式及当前限制统一见 [UI 包说明](../packages/ui/README.md)。

用户最新明确：当前正面立绘仅供配色与风格参考，暂不放入实际页面。`薄荷绿C++发夹少女立绘.png` 原样保存为 [共享参考素材](../packages/ui/src/assets/mascot-mint.png)，仅在明确的品牌设计故事中展示；应用页面与默认认证布局故事不加载该图。保留可选插画接口，待合适的场景素材另行接入，不自行重绘、抠图或裁切；角色正式名称仍待后续设计。

角色配色以薄荷发色与领带、雾蓝发梢、深蓝灰外套和少量浅桃细节为依据，人工拟定色值，不宣称精确取样。浅色主题以暖白表面、深蓝灰文字、浅薄荷选中态组织；主操作使用加深的薄荷绿。暗色主题以外套的深蓝灰建立层级，浅薄荷承载主操作与焦点。浅桃仅作少量装饰，错误、警告、成功等仍保留独立语义，避免整页铺绿或将装饰色用于低对比正文。

参考 nextmoe 的柔和层级、账号中心布局与清晰表单，形成 Moetopia 独立视觉。登录与账号页可以有局部插画、柔和强调色及轻量过渡；授权同意和管理后台优先保证信息可读。

不照搬 NextMoe 名称、logo、角色素材或 KunUI token 名称。图片使用明确授权的本地资源；本轮不创建插画。正式品牌色、字体与 logo 尚待选择，不把候选色写成品牌定稿。

建议以纯色表面和边框建立层次，装饰不影响输入、错误和授权信息。nextmoe 的“任何场景禁止渐变”不是本项目已确认禁令；将来品牌视觉变化在本文件记录。

## Token 层级

| 层级 | 建议语义 | 用法 |
| --- | --- | --- |
| 表面 | background、surface、surface-raised | 页面、卡片、弹层 |
| 内容 | text-primary、text-secondary、text-muted | 正文、说明、辅助 |
| 交互 | action-primary、action-secondary、focus-ring | 主操作、次操作、键盘焦点 |
| 状态 | success、warning、danger、info | 反馈及对应文字/边框/表面 |
| 结构 | border、divider、overlay | 边界、分隔、模态遮罩 |
| 几何与动效 | spacing、radius、shadow、duration | 间距、圆角、层级与过渡 |

上述为语义名称草案，不是已发布 CSS API。组件消费语义变量；原始色板值仅存在于 token 层。明暗主题分别映射同一语义，不在每个页面堆叠独立暗色判断。

状态信息不得只用颜色表达。目标为 WCAG 2.2 AA，具体颜色、字号、焦点和触控尺寸需要实测，不能仅因采用 Headless 就宣称达标。

## Headless 封装边界

- Reka 是当前实现使用的交互底座，负责可组合原语；项目封装视觉、默认交互和稳定 API，不重复手写焦点陷阱和键盘导航。
- 基础 UI 不依赖 Nuxt 路由、具体登录状态、API 或业务角色。导航组件通过明确适配支持 RouterLink 或普通链接。
- 同类复杂控件使用一套原语；发现上游缺陷先复现、核对版本，再选择升级或有记录的适配，不修改依赖安装目录。
- 组件公开 variant、size、disabled、loading 等必要参数；避免无限 class/boolean 组合形成隐含状态。
- loading 不应导致宽度跳动，disabled 不能作为防重复提交的唯一后端措施。
- 基础表单组件负责标签与错误关联；密码强度、OAuth scope 描述等业务内容归应用层。
- 组件修改属于正常维护，不设置“每改一个共享组件都须审批”的规则；破坏性 API 变更需同步所有消费者和故事。

用户已授权先建立可评审的常用组件，再组合页面。当前覆盖基础表单、顶栏与侧栏、菜单与分页、身份展示、反馈与进度、抽屉与弹层、表格与空状态；完整清单和未实现项由 [UI 包说明](../packages/ui/README.md#当前组件) 维护，不在多个文档重复列举。每个公开视觉组件有 Storybook 示例，ToastProvider 与 Toast 组合展示；尚不代表完整组件库或视觉定稿。不预建业务服务或空实现。

当前 Button 提供 sm/md/lg、图标按钮及 solid/bordered/flat/light 变体；为已有页面保留旧 variant/size 别名。Input 提供关联说明和 trailing 操作插槽，密码显隐复用 MoePasswordInput，密码业务规则仍由账号层决定。页框、插画布局、工作区、页面标题、设置行和信息列表均来自共享 UI。图标为本地 SVG 线性图标，无新增图标库。实际颜色唯一来源为 [共享样式](../packages/ui/src/styles.css)，不在页面另设色板；布局样式统一位于 [layouts.css](../packages/ui/src/layouts.css)。

## Storybook 约束

每个公开基础组件至少有默认、交互和关键异常状态；必要时覆盖禁用、加载、错误、长文本、空状态及异步完成。stories 使用固定假数据，不连接生产服务或包含真实账号。

| 检查维度 | 要求 |
| --- | --- |
| 主题 | 同一故事能切换明暗主题 |
| 语言 | 中文和英文示例、长标签不会截断关键含义 |
| 输入方式 | Tab、Shift+Tab、Enter、Escape 等符合控件语义 |
| 弹层 | 焦点进入/返回、滚动锁、层级、移动端可操作 |
| 表单 | 可感知错误，读屏标签关联正确 |
| 动效 | 尊重 reduced-motion，不闪烁、不阻止任务 |
| 文档 | 参数、推荐组合、禁用组合与受控/非受控行为清楚 |

纯 UI 采用 Vue + Vite 故事；依赖 Nuxt 的业务体验通过应用端集成/E2E 检查，不为写故事模拟整套 Nuxt 隐式环境。

Storybook 是组件契约和审阅工具；自动 a11y 扫描不能代替键盘与读屏人工检查。不引入需要额外账号的托管视觉服务作为默认必需项。

## 页面布局与动效

当前组件动效统一定义在 [motion.css](../packages/ui/src/motion.css)，时长与缓动变量由 [共享样式](../packages/ui/src/styles.css) 维护；参数和行为详见 [组件说明](../packages/ui/README.md#交互动效)。Tabs 提供分段滑动底板与滑动下划线，按钮、选择控件和弹层提供克制的状态反馈。尊重系统减少动态效果设置；静态信息组件不循环播放装饰动画。这是当前评审实现，不代表完整页面转场已确定。

登录表单保证窄屏可独立完成，插画可隐藏。授权页突出应用名、来源、scope、允许与拒绝操作；不以装饰诱导用户同意。

后台保持密度可控，危险操作有清楚后果，空页面说明下一步。全局预留稳定滚动条空间并验证浏览器表现，避免主题或路由切换造成布局跳动。

最终视觉验收同时检查两个主题、两种语言、窄屏、错误与加载状态，不只验收默认桌面截图。
