# Go 后端工程规范

状态：Go 模块化单体、Go 统一管理自有 Web 会话、Ent + 独立 SQL 版本迁移为已定方向。工程已采用 chi/Fosite/Huma、pgx 与 Goose，并完成 account 注册、密码和会话基础，见 [ADR-0013](decisions/0013-implementation-baseline.md)、[ADR-0014](decisions/0014-account-preview.md)。完整协议尚未实现，完成程度以 [实施进度](implementation-status.md) 为准。

通用命名、类型、格式和“默认不添加注释”规则见 [代码规范](coding-standards.md)。迁移和协议必要说明遵循该文件，不对每个 Go 导出标识自动生成无信息注释。

## 分层与依赖

按领域组织代码，领域内保留明确的 handler/应用用例/持久化适配职责。禁止建立全项目共用、持续膨胀的 `services` 或 `utils` 集合。

handler 解析输入、调用用例并映射响应；应用层校验权限、编排事务和领域行为；存储适配层使用选定 ORM，必要时使用受控 SQL。领域模型不导入 HTTP、Huma、Fosite、ORM 实体/查询类型或数据库连接。入口负责配置和装配，避免全局连接单例。

仅在测试替换、跨领域边界或多实现确有需要时定义接口；不为每个结构体生成一层镜像接口。错误按语义分类，通过 `errors.Is/As` 判断，不比较错误字符串。

## HTTP 与 API

- 所有请求向下传递 context、取消和超时；不把请求 context 保留给响应结束后的任务。
- 配置请求体上限、header/read/write/idle 超时；具体数值按 endpoint 需求验证。
- 协议端点由协议适配层拥有，不套业务响应包装；业务 API 规则见 [api-contracts.md](api-contracts.md)。
- 鉴权在业务执行前完成，并检查用户、应用状态及资源所有权。外部 client credential 不能通用地访问用户管理接口。
- 只信任配置内的代理来源；Host、Forwarded 和 X-Forwarded-* 不直接决定 issuer 或重定向。
- 结构化日志带 request/trace ID 和必要的脱敏主体；不记录 body、Cookie、Authorization 或验证码。

## 查询、事务与并发

- ORM 优先，不同时引入另一套 ORM 或 sqlc 作为平行 CRUD 层。复杂条件更新和协议存储可在适配层使用参数化 SQL，但与 ORM 共享明确的事务，不形成独立连接提交。
- ORM 模型/schema 是持久化定义，不直接充当 API DTO；跨模块不使用关联预加载或 edges 绕过模块接口。业务用例不能依赖隐式 hook 才完成授权或审计。
- SQL 使用参数化查询，不拼接用户输入；排序字段由白名单选择。
- 查询显式列出字段，限制分页和检索成本；避免 N+1，索引以查询与约束需求为依据。
- 唯一性、条件更新、令牌单次消费等不变量由数据库约束和事务保证，不能仅靠“先查再写”。
- 应用用例负责事务边界，失败回滚；同一事务提交业务状态和 outbox。事务内不调用 SMTP 或其他慢外部服务。
- 密钥轮换、审核生效及刷新令牌轮换必须考虑并发；检查受影响行数，冲突不能伪装为成功。
- 跨模块只调用模块接口；必要跨模块事务须明确参与者，不能直接引用其他模块查询包。
- 存储格式与 API DTO 分开。数据库 nullable、空数组、空对象和字段省略不得靠零值猜测。
- Ent 查询按用例选择字段和加载关联；列表不默认加载完整图。检查实际 SQL、查询次数、扫描行与锁等待，不能用生成代码的类型安全代替性能分析。

## 数据库迁移

采用版本化、可审查迁移；已在共享环境执行的迁移不可改写，后续修复追加版本。禁止服务启动时 `AutoMigrate` 或根据模型隐式改变表。

每次结构变更说明目标模块/schema、现有数据、回填、锁影响、约束、部署顺序和旧版本兼容。大回填分批、可恢复，不把长时间全表改写塞进普通启动事务。

建议 expand → migrate/backfill → contract。破坏性操作必须有备份与回退或前向修复方案；不假设 down migration 能恢复已删除数据。迁移独立运行并加锁，运行账号与普通服务账号权限分开。

已建立并在本项目 Ubuntu 开发库执行首个 authorization schema 迁移，真实测试库迁移亦通过；执行命令与目标库说明见 [工程运行指南](run-foundation.md)。后续业务迁移仍需逐项验证，不能由首个迁移通过推断。

## outbox 与 worker

建议通过 outbox 记录通知意图，在同一数据库事务提交。worker 领取任务时记录租约，成功后确认，失败进行有限指数退避并加入抖动；耗尽后进入可检查、可人工重投的状态。

至少一次处理可能重复发送，不能声称“恰好一次”。业务幂等键与任务投递 ID 分开；验证码重发、审核通知重复与 SMTP 响应丢失都需要明确处理。邮件中必须出现的短期秘密如需排队，载荷加密、限时保存并禁止进入日志；不能以“outbox 只是任务表”为理由明文永久保存验证码。

实例退出时停止领取、等待有界时间、释放或让租约过期。任务 handler 不依赖原始 HTTP 请求 context。默认不持有共享测试环境任务。

## 配置与故障语义

启动时校验必需项，失败说明缺少哪个配置键，不回显秘密。生产 issuer 与登录供应商配置来自受控来源，不根据请求动态生成。

Redis 用于会话或一次性状态时，故障不能回退为已登录；用于缓存时可按拥有者策略回源。审计、限流或撤销检查不可用时的敏感操作拒绝策略应显式定义并测试，不能通用 fail-open。

优雅退出、连接池、HTTP 客户端超时和外部请求重试需要统一配置；不可无界 goroutine、无界重试或以 panic 处理普通业务错误。

## 可观测性与依赖

记录请求延迟、错误率、登录失败、邮件积压、审核积压、令牌轮换冲突与撤销失败。指标标签不包含用户 ID、邮箱、token、client secret 或任意高基数路径。

依赖选择记录维护状态、许可证、漏洞、平台兼容与退出成本。版本由验证后锁定，不盲目采用最新或照抄参考仓库。保留机器语义指令和生成代码标记；不手动修改生成文件。

测试与故障验证要求见 [testing-release.md](testing-release.md)。

性能要求统一见 [performance.md](performance.md)：限制密码哈希并发、数据库池与后台任务并发，区分普通会话读取和密码登录负载。热路径先定位再优化，不能削弱鉴权、哈希强度或事务来提高跑分。
