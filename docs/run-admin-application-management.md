# 管理台应用控制

2026-10-23：管理台应用页面默认显示全部未删除的开发者应用，可切换待审核、分页查看。应用名称与“查看配置”进入详情；行操作菜单与详情页共用同一套审核、暂停、解除暂停和删除交互。内置身份 RP、开发 CLI 创建的裸 OAuth 客户端不属于开发者应用列表，不能混用其凭据管理模型。

详情直接区分最新配置与当前生效配置，展示名称、说明、主页、登录回调、退出回调和 scope，并保留配置版本历史。待审核新版本不会被标成已生效配置；未发布时明确说明按测试规则提供服务。管理接口不返回客户端 secret。

## 管理员删除接口

`DELETE /api/v1/admin/applications/{id}` 使用独立管理员 Cookie、正确 Origin、`X-Moetopia-CSRF`、有效角色与 MFA，JSON 正文为：

```json
{"revision": 3, "reason": "管理员填写的真实操作原因"}
```

revision 必须等于当前应用修订号；reason 去首尾空白后必填，最多 500 个字符。路径是开发者应用 UUID，不是 OAuth client_id。该接口允许对启用、暂停及各审核状态的应用执行删除，不要求先由所有者停用。

同一事务内锁定应用、停用协议客户端、撤销相关授权族及协议状态、标记应用删除并递增 revision、写入操作者/对象/原因/request_id 的审计、为所有者加入通知队列。任一步失败整体回滚，通知入队不代表邮件已送达。

成功返回空 `204`；无有效管理身份/MFA 或来源保护失败拒绝访问，旧 revision 返回 `409`，原因/结构错误返回 `422`，不存在或已删除返回 `404`，基础设施错误返回 `503`。不自动重试删除。前端在冲突后重新读取，名称变化时必须重新输入新名称才能再次确认。

删除沿用项目的逻辑删除模型：普通管理列表和详情不可再访问，所有者不能重新启用；历史数据与审计保留，控制台没有恢复入口。已经离线签发的 JWT 仍可能在其有效期内通过纯离线校验，不能把在线撤销称作所有资源服务器即时失效。

## 更新与验证

无需新迁移或初始化，也不重建签名密钥。部署新 API 与前端即可使用；本轮没有替日常账号删除任何应用。OpenAPI 和类型由生成器更新，文档目录自动包含新增端点。

已用 `pnpm test:integration` 的随机专属数据库验证 MFA、Origin/CSRF、原因、revision、成功删除、在线令牌失效、审计留存、所有者不可恢复、单连接事务与审计失败回滚。页面测试使用合成应用，验证操作菜单、最新/生效配置、批准、暂停、名称确认、删除后的列表以及冲突后的重新确认；真实管理员浏览器登录检查的具体结果见 [前端交接](coordination/frontend.md)。
