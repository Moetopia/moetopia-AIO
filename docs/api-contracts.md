# API 契约与兼容规范

状态：目标契约规范。已实现基础状态、account 和授权交互业务 API，OpenAPI 和 TypeScript 从真实 Huma 路由生成。授权码/OIDC 已有后端实现，当前可用路径及未完成能力见 [授权接入](run-authorization.md)；下表完整清单仍为目标，不能据表假定已全部开放。协议依据见 [身份与安全](identity-security.md)，实际进度见 [实施进度](implementation-status.md)。

## 两类接口

| 类别 | 目标约定 | 拥有者 |
| --- | --- | --- |
| OAuth/OIDC | 标准字段、HTTP 语义、header、重定向和错误 | authorization 协议适配层 |
| 业务 API | `/api/v1`，JSON、OpenAPI、统一资源与错误语义 | 相应业务模块 |

不得给 token、userinfo、撤销等标准响应增加 `{ code, message, data }` 外包装。撤销成功不强制返回 JSON；授权端点存在协议重定向，不强制套 JSON 错误。

## 建议协议端点清单

下表是路径提议，不可据此调用；公开发行前通过 discovery 和契约定案。

| 能力 | 建议路径 | 说明 |
| --- | --- | --- |
| OIDC 元数据 | `/.well-known/openid-configuration` | issuer 固定配置，仅声明实现的能力 |
| 公钥 | `/oauth/jwks` | 路径由 jwks_uri 公布，不含私钥 |
| 授权 | `/oauth/authorize` | 以授权事务驱动登录及同意 |
| 令牌 | `/oauth/token` | 标准 form 编码与客户端认证 |
| 用户信息 | `/oauth/userinfo` | 仅披露获准 claims |
| 撤销 | `/oauth/revoke` | 标准撤销语义 |
| 内省 | `/oauth/introspect` | 认证并限制调用方 |
| 退出 | `/oauth/logout` | 按 OIDC 退出参数及注册地址验证 |

不要将协议表中的路径看作必须有特定前缀的标准要求。OAuth/OIDC 客户端依赖元数据及文档，不解析自家页面路径。首期不开放 RFC 动态客户端注册，开发者门户自助创建是业务能力。

## 业务 API 建议

成功响应直接表达资源；列表统一 `items` 与不透明的 `next_cursor`，没有后页时建议 null。首期不另套全局成功信封；该选择尚待确认。分页使用确定排序和绑定筛选的游标，限制 page size，具体上限待负载验证。

错误建议采用 [RFC 9457 Problem Details](https://www.rfc-editor.org/rfc/rfc9457.html)，使用 `application/problem+json`，补充稳定业务 `code`、字段错误和请求关联 ID。`type` 表达问题类型，具体 URI 待正式域名确定；客户端不通过匹配中文或英文 detail 分支。核对日期：2026-10-17。

HTTP 状态表达结果：401 未认证、403 无权限、404 不存在或按策略隐藏资源、409 状态冲突、422 内容校验错误、429 限流、5xx 服务故障。协议端点错误保持各自规范，不按此表机械改写。

## 模型与权限

- JSON 字段建议 snake_case；业务时间使用带 UTC 标识的 RFC 3339 字符串，令牌时间遵守其协议定义。
- ID 为不含个人信息的稳定字符串，格式待选。可省略、null、空数组的区别显式写入 schema。
- 金额或将来精确计量不依赖浮点隐含精度；首期不提前增加计费字段。
- 输入只允许明确可写字段，禁止客户端提交 owner、管理角色、审核状态或邮箱验证状态来扩权。
- 每个操作定义认证主体、scope、角色和资源所有权；用户令牌与应用令牌分别建模。
- 更新状态或审核配置建议使用版本/条件写入；并发冲突显式失败，避免覆盖他人修改。
- 需要重试的写操作单独定义幂等键、有效范围及相同键不同请求的冲突规则，不假设所有 POST 自动幂等。
- 跨服务不以“知道 client secret”换取任意批量用户查询权限。批量接口按实际使用建立最小授权。

## OpenAPI 与生成

业务 API 建议由 Huma 类型定义生成 OpenAPI，作为生成客户端类型的来源。生成产物与运行路由必须在 CI 对照；文档阶段不创建空 OpenAPI 伪装接口可用。

生成类型位于共享 API 包，不手工维护第二份 DTO，也不编辑生成文件。生成器与版本锁定，产物可重复生成。标准 OAuth/OIDC 使用标准客户端库，不要求第三方依赖业务 SDK 才能登录。

示例使用假数据和保留示例域名；不包含 token、生产地址或真实用户。协议测试可由官方语义与独立标准客户端驱动，不只测试自家 SDK。

## 兼容与文档同步

新增字段先考虑客户端是否允许扩展；改名、删字段、收窄枚举、改变 null/权限/错误语义按破坏性变更处理。稳定版本的破坏性变化需要版本与迁移说明，不把所有变化都包装成“内部重构”。

契约变化同时更新拥有者文档、OpenAPI、生成类型和示例。尚无实现时本文件是设计提议；有实现后以测试证明代码符合契约，差异必须修复或明确记录，不能用“以代码为准”掩盖漂移。
