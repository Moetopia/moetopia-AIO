“类似 Logto”指身份服务的产品定位，不是完整功能复制或界面复制承诺。

## 用户角色

| 角色 | 目标 | 边界 |
| --- | --- | --- |
| 普通用户 | 使用统一账号登录、管理资料和授权 | 只能操作自己的账号与会话 |
| 应用所有者 | 创建测试应用、申请正式接入、管理凭据 | 只能管理自己拥有的应用 |
| 平台管理员 | 审核应用、处理账号与安全事件 | 管理权限单独授予并留审计 |
| 应用后端 | 校验令牌、调用获准 API | 不读取身份数据库，不继承用户全部权限 |

首期建议单人应用所有权；团队成员管理、组织管理员和所有权转移的产品流程留待后续。第三方 OAuth 应用不等于身份租户。

## 建议首期能力

以下是可交付范围草案，除 C01–C20 明确选择外，细节未获用户确认。用户表达倾向 JWT，具体签名、撤销与时效方案尚未确认，见 ADR-0012。

当前规模是产品预期，不是已经测得的 DAU、同时在线人数或 RPS。类 pixiv 社区仅说明未来生态形态，不把作品上传、推荐、搜索或社区实现加入本期身份产品。

| 能力 | 首期建议 | 需要进一步确认 |
| --- | --- | --- |
| 账号 | 验证邮箱、注册、密码登录、密码恢复、修改邮箱及基础资料；后台切换开放/邀请模式，默认邀请已确认 | 邀请发行与兑换流程、资料字段 |
| 联邦登录 | GitHub、Google 登录及绑定解绑 | 首次登录与邮箱冲突交互 |
| 授权 | 标准 OIDC 登录、API scope、同意与撤销 | 具体授权范围与时效 |
| 会话 | 当前设备、设备列表、撤销会话、RP 发起退出 | 是否首期承诺跨站同步退出 |
| 开发者 | 创建测试应用、配置回调、申请权限、提交审核及密钥管理；发布后敏感变更版本化审核已确认 | 审核状态机细节、配额 |
| 后台 | 用户检索、封禁、应用审核、应用暂停、安全审计 | 管理角色粒度 |
| 管理员安全 | 已确认首期包含一次性初始化、TOTP MFA、单次恢复码；CLI 为建议初始化方式 | 初始化载体、恢复权限与流程 |
| 账号生命周期 | 注销申请及清理流程、通知和撤销 | 冷静期、数据保留及下游清理策略 |
| 接入资料 | 一个独立示例客户端与标准 OIDC 库接入指南 | 首期示例语言 |

账号注销不等于本轮承诺实现法定数据处理流程；具体产品政策需先定案。首期至少在上线前明确暂停、注销、审计保留与删除之间的关系，不能默认永久保存。

## 受控自助接入目标

已确认：开发者能够自助创建测试应用，正式开放前需要管理员审核。

建议流程：草稿 → 测试 → 待审核 → 已发布；拒绝允许修改后再次提交。另设平台暂停和所有者停用能力。测试态仅允许所有者和显式测试成员授权。

已确认：发布后，回调地址、权限及应用身份展示的敏感变更生成待审核版本；原批准配置继续服务，新配置获批后生效。待审配置不得提前进入授权判断。建议紧急停用立即生效；版本并发、生效和拒绝的细节见 [ADR-0008](decisions/0008-application-config-review.md)。

应用审核只代表获准接入，不代表平台为其内容或安全作背书。授权页必须展示真实应用身份、申请权限及联系信息。

## 成功标准

- 用户能注册并通过标准 OIDC 客户端登录两个示例站点，第二个站点可使用已有身份会话。
- 开发者能独立完成测试、提交审核及正式接入；未审核应用无法对普通用户开放。
- 用户能撤销授权和会话，管理员能暂停应用；撤销传播边界有明确文档和测试。
- 中英文、明暗主题、移动端、键盘交互均可完成关键任务。
- 后续增加业务模块时，不必复制账号系统或让模块直接读取身份表。

## 首期排除项与后续路线

首期不做独立用户池、多租户 issuer、组织邀请、企业 SAML、动态客户端注册、通用插件市场、计费、原生移动 SDK、图床、文件平台、论坛或 Kubernetes。普通用户 MFA 已确认后置，Passkey 建议后置；管理员 MFA 属于首期范围。

下一阶段优先：开发者团队、Webhook、API 资源治理、调用额度与运营工具。图片、文件、社区等模块随后按实际需求加入，不预建空实现。不迁移 nextmoe 的用户或数据。

架构实现建议见 [architecture.md](architecture.md)，所有待决定事项统一在 [决策索引](decisions/README.md) 维护。
