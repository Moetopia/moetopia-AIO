# 开发环境与配置设计

状态：Windows 原生开发、Compose 依赖、Linux 容器生产为已定方向。已建立开发脚本、页面壳、API 与开发 Compose；当前命令和前置条件统一见 [工程运行指南](run-foundation.md)，执行证据见 [实施进度](implementation-status.md)。生产部署配置尚未交付。

## 目标运行方式

PowerShell 启动 Nuxt 与 Go，Docker Compose 提供 PostgreSQL、Valkey 与开发邮件 Mailpit。Nuxt 支持热更新；`pnpm dev` 监视 Go 源文件并自动重新构建 API，迁移仍需显式执行。无需 Git Bash、WSL 或 host networking。日常操作见 [开发预览](live-development.md)。

工程采用 Valkey 客户端与开发容器定义，真实认证连接与基础协议集成已通过；完整限流边界和故障恢复仍待测试。开发与未来生产的协议兼容要实际验证。

宿主进程连接 localhost 映射端口；容器连接 Compose 服务名。不得混淆 Windows localhost 与 Docker VM loopback。只将开发所需端口绑定到本机；正式生产不对公网开放数据库、Redis 或开发邮件面板。

开发 issuer、端口和项目标识已在本项目示例与运行指南定义。生产域名及入口尚未定案，不能把开发默认值直接用于生产，不能复制 nextmoe 的资源。

## 工具与版本

工具版本与启动命令见 [工程运行指南](run-foundation.md)。版本通过 go.mod、工具依赖与 pnpm 锁文件记录；Windows 不安装 Docker，已使用 Ubuntu 的 Docker/Compose 完成依赖启动与真实集成验证。

所有目标流程需要在包含空格的 Windows 路径验证，避免 Bash 专属环境变量写法、路径分隔符和依赖 Unix 权限语义。PowerShell 脚本不能把删除路径拼接交给其他 shell；清理前验证绝对路径与所有权。

## 操作接口要求

下表是完整能力要求，不能视作全部已经实现。实际脚本见运行指南；环境体检当前检查工具和 Docker engine，不代替端口、数据库或配置的完整验收。数据重置入口尚未提供。

| 能力 | 目标行为 |
| --- | --- |
| 环境体检 | 只读检查工具、Docker、端口、数据库可达及配置完整性；错误指出修复方向 |
| 依赖启动 | 启动本项目数据库、Valkey、Mailpit，不影响其他项目 |
| 应用开发 | 启动所选 Go/Nuxt 应用，输出清晰日志，Ctrl-C 只清理本轮进程 |
| UI 开发 | 独立运行 Storybook，无需身份服务或真实账号 |
| 迁移 | 显式目标数据库、版本和执行结果，禁止隐式初始化生产 |
| 测试资源 | 为当前测试分配独立数据库与缓存命名空间，可按所有权清理 |
| 依赖停止 | 停止本项目容器；默认不删除数据卷 |
| 数据重置 | 单独显式入口，检查环境与目标，只作用于专属开发/测试资源 |
| 契约生成 | 生成 OpenAPI 和客户端类型，并能检查漂移 |

新增命令必须同步脚本与运行指南，区分代码存在、本机验证通过和依赖环境下实际运行通过。

## 配置所有权

| 配置类别 | 设计约束 |
| --- | --- |
| 公开浏览器配置 | 仅非秘密的品牌、公开 URL 和功能展示信息 |
| 服务端配置 | 数据源、SMTP、OAuth 凭据、签名/加密密钥、代理白名单 |
| 身份协议配置 | 固定 issuer、获准回调、客户端类型、scope，不能由请求头修改 |
| 测试配置 | 专属测试数据库、端口和缓存命名空间，与开发/生产分离 |

`.env.example` 只提供开发占位值；初始化脚本生成随机本地密码和加密密钥，以独占写入方式创建 `.env`，不覆盖既有文件。忽略规则已建立。生产配置必须独立管理，不能沿用开发凭据。

配置缺失在启动时清楚失败。没有 GitHub/Google 凭据时可在开发隐藏对应入口并显示配置状态，不冒充登录成功；生产启用的供应商必须具备有效配置。

## 数据与秘密

开发种子使用合成账号，测试不导入生产快照。检查 DSN 时不输出凭据；数据库连接日志只打印安全主机与资源标识。验证码、恢复码等只在明确的开发投递工具内按用途查看，不进入应用通用日志。

测试只能使用明确分配的资源，缺少资源时中止相应测试并报告，不读取普通 `.env` 猜测测试库。运行集成测试前验证目标数据库身份；清理数据库不使用任意用户输入拼接 SQL 标识符。
