# 代码规范

状态：项目编码与评审规范；注释策略按用户要求确认。项目已按后续用户指令进入实施阶段，当前交付范围见 [实施进度](implementation-status.md)。规范本身不额外授权提交、部署或修改其他项目。

参考 nextmoe 的简洁表达、页面拆分和注释原则，适配 Moetopia 的 Go、Nuxt 与 Ent 方案。专项架构见 [前端规范](frontend.md)、[后端规范](backend.md) 和 [设计系统](design-system.md)，本文件不另行定义技术选型。

## 1. 注释：默认不添加

**非必要不添加注释。只有代码本身不能清楚表达、且维护者必须知道的信息，才使用注释解释。** 这里的“注释”包含 Go/TypeScript 行注释、块注释、JSDoc、Vue/HTML 注释和 SQL 说明。

先改善命名、拆分职责和控制流，再判断是否仍有必须解释的原因。不得给每个函数、字段、分支或步骤自动生成注释，也不为了让代码“显得完整”增加说明。

### 必要注释的判断

满足以下情形且不能通过代码结构清楚表达时，允许写简短注释：

- **安全或并发不变量**：为何必须按特定顺序消费、为何不能合并两个状态、为何条件更新不能改成普通写入。
- **协议与外部约束**：不直观的标准要求、上游缺陷、版本限制或有意偏离常见写法的兼容措施；必要时附官方条款、issue 或版本依据。
- **迁移和历史**：现有数据如何处理、约束为何分步建立、哪些旧值必须保留；不逐行翻译 DDL。
- **算法或性能取舍**：为何采用不直观但必要的方法、适用条件和退出条件；不能用没有测量依据的“更快”作为理由。
- **公开契约**：对外复用接口存在无法从类型/名称得知的语义、所有权或生命周期。内部标识不因导出就自动生成无信息的注释。
- **工具要求**：选定检查工具确实要求公开文档时，写有实际语义的最小说明，不通过整包关闭检查回避。

不要求先发生事故才允许记录必要约束；同时不能以“以后也许有人不懂”为由注释所有代码。

### 不应添加的内容

- 复述语句，例如 `// Get the user`、`// Return the result`。
- 重复名称，例如 `// New creates a new Service`。
- 装饰性分区，如“初始化”“业务逻辑”“辅助函数”横幅。
- 修改记录、作者签名、对话过程或“AI generated”说明。
- 无具体约束、责任或去向的 TODO/FIXME；确有延后事项时关联明确任务或 issue，说明未完成行为。
- 注释掉的旧实现、临时调试代码、日志和过时方案。需要的历史由版本管理保存。

注释用简短英文，解释**原因或约束**。真实错误输出、标准原文、产品文案可以保留原语言。变更代码时核对相邻注释是否仍正确；不以本规则为由批量删除无关文件中的说明。

### 机器指令与生成内容

`//go:embed`、`//go:build`、`//go:generate`、生成文件标记、`//nolint`、`eslint-disable`、`@ts-expect-error` 等可能具有机器语义，不能当作多余注释删除。

新增检查豁免需要确有原因、作用范围尽可能小，并符合相应工具要求；不使用文件级豁免掩盖普通类型或逻辑错误。必要理由属于允许的注释。

生成文件从源定义重新生成，不手动增删注释；保留上游许可证和法律声明。

## 2. 命名与文件组织

- 标识使用清楚的英文业务词，避免无意义缩写、拼音以及 `data`、`manager`、`helper` 等缺少上下文的名称。
- Go 包名遵循语言惯例；Vue 组件使用 PascalCase，composable 使用 `useXxx`，布尔值使用能表达判断的名称。
- 常量归拥有它的功能模块，不集中到全项目万能常量文件。真正稳定的共享语义才提升到共享包。
- 文件围绕一个职责组织，约 300 行时评估，约 500 行时优先拆分；不把行数当作自动拆文件指标。
- 共用代码由公开入口导出，不跨目录访问其他模块私有实现；不引入循环依赖。

## 3. 实现与类型

- 优先直接、可读的实现；避免过深嵌套、无必要抽象和布尔参数堆叠。
- 提前返回可读的错误路径。对未知外部输入做必要校验，对内部已保证的不变量不反复堆叠相同防御分支。
- 不吞掉错误，不用空数组、零值或固定成功响应掩盖依赖失败；用户可恢复的错误与内部故障分别处理。
- 不用类型断言冒充运行时验证；数据库模型、领域数据和 API DTO 按边界转换。
- TypeScript 采用严格类型目标；外部未知数据使用 `unknown` 并缩窄，不随意用 `any` 或非空断言绕过检查。
- Go 传递 context，检查资源关闭与事务结果；不以 panic 处理正常业务错误，不启动无界后台任务。
- 前端自定义函数默认箭头函数，Vue 使用 Composition API；共享组件不能依赖具体账号、API 或后台角色。
- Ent 生成实体与查询留在适配层；必要 SQL 参数化、共享明确事务，不把数据库约束替换为先查再写。

## 4. 格式与可读性

Go 格式以 `gofmt` 为准；前端格式与静态检查由工程初始化时配置的统一工具决定，不让不同应用采用冲突规则。当前尚无格式化脚本，不把计划命令当作现成命令。

正常变更只格式化相关文件，不夹带全仓风格修改。导入按工具整理，移除未使用代码，不使用长相似代码块或横幅代替职责拆分。

复杂表达式可以拆为有意义的中间值；不为减少行数写难读的链式调用或嵌套三元表达式。必要重复可接受，抽象必须减少理解成本。

## 5. 变更与评审

- 一次改动围绕明确目的，检查受影响调用方、错误语义、权限与空值行为。
- 新增或改变共享组件时同步必要 Storybook 状态；改变业务契约时同步拥有者文档与类型生成来源。
- 数据结构演进保留可审查迁移和兼容说明；不得启动时自动改表。
- 测试验证行为与不变量，避免只镜像实现；纯文档或机械格式修改不新增业务测试。
- 性能优化有场景、测量和正确性证据，不削弱安全或事务；详见 [性能规范](performance.md)。

评审注释时只问：删掉它会不会丢失维护所必需、且代码无法表达的信息？如果不会，应当删去或不添加。
