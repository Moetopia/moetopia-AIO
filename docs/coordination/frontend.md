# 前端进度与后端接入反馈

更新时间：2026-10-19。所有者：前端/UI 对话。工作前已读取 [同步规则](README.md) 与 [后端状态](backend.md)；不代表已自动向另一对话送达通知。

## 新用户决定：自有中心也通过 OAuth/OIDC 登录

2026-10-19 用户明确否定当前布局与登录链路，要求用户中心、开发者中心都通过 OAuth 登录。此前“用户站继续直接消费身份 Cookie 即可”的实现不能作为最终方案。Go 持有服务端会话、HttpOnly Cookie 和令牌不进入浏览器存储的约束仍保留；需要区分身份提供者认证会话与自有 RP 会话，避免授权页登录回到自身产生循环。

后端待接：为自有 account/developer（合并站点可共享一个 RP）实现受控客户端注册、登录启动和回调、服务端 PKCE/state/nonce 单次事务、固定回调与站内返回路径校验、授权码兑换及 ID Token 完整校验、独立 RP 会话建立/失效/退出。前端需要 Go 提供稳定的启动入口和 RP 上下文契约，再替换当前直接登录用户站的入口；不能假装现有密码登录已经经过 OAuth。管理员 RP 同理，且权限/MFA 必须由后端执行。不得为了接线把令牌放到 localStorage 或在 Nuxt 另建身份系统。

布局本轮改为严格按参考源码的结构、尺寸和导航分工实现；保留 Moetopia 文案/配色、不放立绘。授权 UI 增加独立 `/auth/authorize` 路由，首页旧事务入口保留；`/oauth/authorize` 仍归 Go 协议端点，不被页面路由或代理覆盖。当前协议成功后 Go 仍重定向旧事务入口，可由后端后续改为独立 UI 路由。没有自动发送跨对话通知。
