# 首次生产发布的前端验收交接

目标是在生产镜像和真实域名上验证现有页面。前端对话负责页面、浏览器行为和必要修复。后端对话负责 Compose、首装命令、认证契约及服务端故障。

| 优先级 | 场景 | 通过条件 |
| --- | --- | --- |
| P0 | 用户站和管理台生产产物 | 两个 HTTPS 域名首次访问、直接打开深链接和刷新均可用。管理台静态回退正常，插画、字体和共享 UI 资源加载成功。浏览器请求指向正确 origin。 |
| P0 | 首位管理员 | 用户站用首装邀请码、实际邮箱验证码和本地密码注册。运维完成角色初始化后，从管理台登录、绑定 TOTP、保存恢复码并进入后台。MFA 前访问管理接口被拒绝。 |
| P0 | 第三方应用 OIDC | 创建应用并登记精确 HTTPS 回调。用独立应用完成登录、同意和回跳，确认浏览器重定向与 Cookie 未被代理吞掉。检查登录及中央退出确认页可直接加载。 |
| P0 | 开发者和文档 | 进入开发者中心和站内文档，确认生成契约包含两种 Discovery 地址。检查创建应用、测试成员、审核入口和上线后的状态显示。 |
| P1 | 可选外部登录 | 供应商未配置时入口隐藏。配置后逐家验证首登补全、绑定及拒绝回调，保留原流程的浏览器状态。 |

生产入口与命令见 [Linux 容器发布](../run-production.md)，OIDC 字段见 [客户端配置](../configure-oidc.md)。首装邀请码通过运维命令发放，注册页继续消费既有邀请码字段。使用专用验收账号和应用检查拒绝、撤销等状态。

发现问题时在前端交接记录提交、环境、复现步骤、预期与实际、请求路径和状态码。Cookie、验证码、令牌、密码和邀请码不进入记录。发现契约或代理问题时附脱敏请求信息交回后端。发布记录应区分容器演练、真实浏览器验证和目标域名验收。
