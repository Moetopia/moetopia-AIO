## 建议决定

PostgreSQL 建议作为权威存储，Ent 已选为 ORM 文档基线，见 [ADR-0010](0010-orm-comparison.md)。连接驱动与迁移工具随 Ent 验证，独立 SQL 版本迁移优先评估 Goose。首期建议一个应用数据库，按模块 schema 组织。缓存层需比较 Valkey 与 Redis，暂未选定，用于会话、一次性状态及多实例限流的故障语义需分别设计；不可把唯一业务真源放在可丢弃缓存。

邮件通过 PostgreSQL outbox 与独立 worker 投递，不引入消息队列。密码使用 Argon2id；具体参数需在目标硬件压测。

## 理由与代价

ORM 优先符合用户的模型维护偏好。身份数据依然依赖事务、唯一约束及并发条件更新，ORM 不取代 SQL 审查和数据库一致性。schema 分区不等同于独立数据库的权限隔离。

Redis 增加一个运维依赖；缓存、会话和限流不同用途需要明确过期、持久化和驱逐策略。outbox 只承诺至少一次处理，需要幂等和失败恢复。

## 替代方案

原 pgx/sqlc 主数据层和 GORM 是本轮未采用的方案。采用 Ent 不改变显式迁移要求；受控原始 SQL 可在适配层处理复杂原子操作，不另建平行 CRUD 框架。PostgreSQL 会话可减少缓存层依赖，采用前需比较故障语义和容量。

## 待验证与重新评估

按 Ent 基线比较独立迁移执行器和结构对照方式，不采用运行时自动改表。具体资料和代价见 ADR-0010；缓存许可与运行成本见 [全栈复核](../stack-review.md)，尚未验证版本及许可证组合。
