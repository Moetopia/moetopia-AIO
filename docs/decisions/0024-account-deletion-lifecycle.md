# ADR-0024：七天注销、显式取消与模块清理

- 日期：2026-10-21。
- 状态：已授权范围内的工程实现；七天冷静期与先停用已发布应用沿用实施基线。具体数据政策不视为生产合规批准。

身份表使用独立的可空注销请求/截止时间，不复用 enabled，避免取消注销绕过平台冻结。正常身份读取/登录/会话签发排除 pending，资料 CAS 和安全版本防止旧请求越权；恢复密码仍可使用但不自动取消。取消要求当前密码与目的隔离的邮箱挑战，在锁后重新检查真实截止时间，不恢复任何旧会话或授权。

注销前检查已发布应用和管理员保护，停用测试应用；业务、凭据、会话、审计和通知同一事务。lifecycle 是跨模块用例编排，数据删除由各模块命令负责，不越界读写其他 schema。到期采用持久 pending 状态、有限批次和跳过已锁用户；每用户原子完成，失败可重试。授权清理恢复旧加密快照的缺失归属，不依赖开发库曾经执行过一次回填。

选择物理删除用户与关联身份资料，释放邮箱；审计保留匿名 UUID 至原 90 天期限。通知增加主体标记以清除队列，既有短期邮件在七天前过期；外部已投递邮件、离线 JWT 及下游数据不在事务撤销范围。删除本身不自动向第三方发送 Webhook；未来下游清理必须设计真实投递和确认协议。

代价：生命周期依赖本地模块事务，未来拆服务须重设计一致性；单个重度用户的历史清理成本需实测。正式数据政策、第三方数据处理、留存/申诉、管理员注销与服务降级是重新评审条件。接口、迁移 10、错误和验证边界由 [运行契约](../run-account-lifecycle.md) 维护。
