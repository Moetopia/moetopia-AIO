# ADR-0013：工程实施基线与验证边界

- 状态：已进入实施；本文记录当前工程选择，不宣称完整产品或生产验收完成。
- 日期：2026-10-18。
- 背景：文档准备完成后，用户要求开始实施；Windows 不安装 Docker，用户后续提供 Ubuntu `192.168.101.41` 的 SSH 开发环境。已在专属目录与网络启动依赖，宿主机端口统一为容器端口加 50000。

## 当前工程选择

| 部分 | 当前实现 | 边界与代价 |
| --- | --- | --- |
| 前端 | 三个 Nuxt 应用，共享 Reka/Tailwind UI、翻译与 Nuxt 层 | account 为 SSR，admin/developer 为静态 CSR；当前只有页面壳，无账号或审核流程 |
| 组件验证 | Storybook 与 Playwright | 已验证基础交互，不等于完整 WCAG 或业务验收 |
| HTTP 与协议 | chi、Huma、Fosite | Huma 仅用于业务接口；Fosite 当前只装配 client_credentials，授权码、刷新、OIDC 尚未实现 |
| 数据 | PostgreSQL、Ent、pgx、Goose 独立 SQL | authorization schema 的迁移、模型持久化及基础集成通过；尚未覆盖后续授权码与刷新并发事务 |
| 缓存 | Valkey 与 valkey-go | PostgreSQL 保持权威；当前用于限流及就绪检查，服务不可用时敏感端点拒绝 |
| 令牌基础 | RS256、JWKS、十分钟 client_credentials access token | 私钥加密保存；真实签发、重开连接恢复及状态撤销已通过基础集成，不代表所有业务令牌策略定案 |

依赖版本由锁文件与 Go module 记录，不在本文重复维护。共享层增加 `packages/portal`，承载 Nuxt 页面壳与应用级偏好逻辑；纯 UI 包不承担身份业务。

## 与早期记录的关系

ADR-0003/0004/0005/0007/0012 保留文档准备阶段的候选、理由及风险；当前实际采用的工具以上表为准。采用候选不消除其验证门槛，尤其不能以 Fosite 编译成功替代授权码消费、刷新轮换和退出互操作验证。

账号默认邀请注册、Go 管理浏览器会话、管理员 MFA 和应用配置版本审核继续作为目标约束。注销与审计生命周期的当前实施范围见 [实施进度](../implementation-status.md)，尚无对应业务实现。正式域名、生产资源、许可证、邮件供应商和恢复目标仍未确定。

## 验证与重新评估

- 已通过与未执行的检查只在 [实施进度](../implementation-status.md) 维护；运行前置条件见 [工程指南](../run-foundation.md)。
- 已连接真实 PostgreSQL/Valkey 通过基础集成测试，并修正 migration SQL 关键字引用。后续协议流程仍须增加对应集成证据，不得用 mock 替代数据库并发验证。
- 开始授权码或刷新流程前补齐原子消费、轮换、撤销与并发测试，不能复用现有 access-token 存储后直接宣称完整协议兼容。
- 依赖审计的未修复告警见 [审计记录](../dependency-audit.md)；发布前评估上游修复或替代路径，不添加忽略列表使检查表面通过。
- 任何选型出现维护中止、许可证限制、无法满足协议正确性或端到端资源目标时，记录证据并重新评估。
