# ADR-0001：已确认产品与技术方向

- 状态：已确认，依据用户在本次讨论中的选择。
- 记录日期：2026-10-17。
- 实施状态：未实施。

## 背景与决定

Moetopia 先做生态统一身份中心，之后扩展为多模块平台，优先发展开发者开放平台。采用共享账号，不为每个应用建立独立身份租户。

前端选择 Nuxt + Vue + TypeScript；组件采用 Headless + Storybook。首期中英双语、明暗主题及轻二次元体验。用户登录包括邮箱密码、GitHub 和 Google；开发者受控自助创建测试应用，正式接入经过审核。

以 Go 后端为设计前提，具体库继续讨论。Windows 原生开发、Compose 依赖、Linux 容器生产是环境方向。当前只完成和调整 Markdown 规范，工程实施单独授权。

## 理由与代价

统一身份降低生态重复建设成本；共享账号需要清晰的应用权限边界。Nuxt 接近参考项目的 Vue 实现方式；自有 Headless 组件带来品牌自由度，也要求维护可访问性、主题和 Storybook。

Go、Nuxt、Headless 的方向不证明任何具体版本组合可用。

## 不包含的决定

未确认 Reka/Tailwind 的具体采用、Fosite、chi、Huma、数据库与缓存、管理员 MFA、目录结构、域名及保留期限。详细状态见 [索引](README.md)。

## 重新评估条件

用户修改产品定位、主要维护团队技能变化、目标部署环境不可满足，或关键兼容验证表明成本不可接受时，提出后继 ADR；不在实现过程中擅自换栈。
