最后整理：2026-10-19。ADR 区分设计历史、用户确认与实际实现；依赖安装不等于完整功能或生产验证通过。当前实施基线见 ADR-0013，早期评审记录按当时阶段保留。

## 状态规则

- **已确认**：用户明确选择的方向；具体兼容性仍需验证。
- **建议**：推荐方案，可以讨论和替换；编写该 ADR 不等于用户确认。
- **已替代**：保留原理由并链接后继 ADR，不悄悄改写决策历史。
- **待验证**单列在 ADR 内，说明采用前需要的证据。

用户确认后，在原 ADR 记录日期、确认范围和结论，并同步受影响文档；不能仅因开始编码把状态改为已确认。

## 第三轮结论与技术建议

用户明确要求按长期、专业化、工程化及商业项目尺度选型，已写入 [长期工程原则](../long-term-engineering.md)。用户未指定 Ent/GORM；本轮给出 Ent + 独立 SQL 版本迁移的工程建议，并记录 Atlas 的能力与许可边界，等待确认与未来验证。

用户询问 nextmoe 的 token 实现并表达 JWT 倾向；源码核对与 Moetopia 建议写入 ADR-0012。倾向不等于具体算法、TTL 或撤销模型已经批准。

邀请码已选择管理员创建、不绑定邮箱、单次兑换、可到期和撤销；不再询问是否绑定邮箱，具体限额和时效仍待定。

## 后续确认与全栈复核

2026-10-17，用户选择 Ent 方案作为文档基线，接受独立可审查 SQL 迁移、优先评估 Goose、不默认依赖 Atlas Pro，并要求复核之前的框架与性能。第三轮中的 Ent 未决状态由本次结论更新；不因此授权工程实施。

[全栈复核](../stack-review.md) 保留已确认方向，继续推荐 chi/Reka/Tailwind，Huma 限业务 API，Fosite 保持候选并强调生产存储验证；缓存新增 Valkey 比较。渲染方式与新增工具均为建议，没有静默替换已确认框架。

[性能规范](../performance.md) 定义端到端场景与资源预算，负载及 SLO 数值仍待确认。上一轮 JWT 问题未收到单独回答，仍保持用户倾向与方案建议，不改为已确认。

用户随后补充：生态预计低流量，最多可能发展为类 pixiv 社区，活跃用户最多双位数；硬件未定。该信息作为规模预期记录，不推算 RPS。首期建议单机与最小依赖，性能验证分阶段；无需继续追问精确硬件才能完成本轮文档。未来社区不属于首期实施范围。
