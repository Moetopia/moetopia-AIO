# ADR-0021：开发者应用与生效版本

- 日期：2026-10-19。
- 状态：用户已确认的受控自助及旧批准版继续服务方向已实现；所有者前端已接，管理员 RP/MFA 和审核/暂停入口由 [ADR-0022](0022-administrator-security-and-review.md) 完成后端，后台页面待接。
- 扩展：[ADR-0008](0008-application-config-review.md)。

developer 持有应用所有权、revision、latest/active 指针及配置版本，authorization 独占协议 client 和令牌状态。developer 通过协议模块命令在显式共享事务中安装、停用或轮换受管 client，不直接操作协议表。固定自有 RP 不属于受管应用命名空间。

初始草稿安装仅所有者可授权的测试配置；首次批准后对普通用户开放。发布后名称/回调/scope 等都进入新 draft/pending，拒绝不改变生效配置。批准时原子安装新配置并切换版本；失败保留旧配置和旧凭据。当前保守选择在新配置生效时撤销原授权族，而非试图判断每一种 scope/回调差异的兼容性，代价是用户需要重新授权。

应用 revision 保护并发编辑，配置 version 记录审核内容，二者不混用。配额按用户行锁串行检查；协议事务与配置变更协调同一 client 的共享/排他锁，授权族按确定顺序加锁。secret 创建/轮换只返回一次，保存 bcrypt 哈希；无自动幂等重试，也不提供可逆秘密查看。

所有者停用与软删除已实现；2026-10-19 平台暂停已作为独立 suspended 状态接入，所有者 enabled 不能覆盖暂停。Review 仍是内部领域命令，其 HTTP 适配层必须经过 ADR-0022 的独立管理员角色/MFA 事务校验，不存在匿名或开发后门。

契约、开发额度、迁移 7 和真实测试由 [开发者应用接入](../run-developer-applications.md) 维护。重新评估条件：管理员审核接入、平台暂停、应用所有权转移、测试成员、历史版本查询、通知，以及用户重新授权成本需要更细的兼容策略。
