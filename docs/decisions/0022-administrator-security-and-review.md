# ADR-0022：独立管理员身份、MFA 与受控后台事务

- 日期：2026-10-19。
- 状态：首期已授权范围的工程实现；开发参数不等于生产配置确认，验证与运行事实见 [管理员接入](../run-administration.md) 和实施进度。
- 扩展：ADR-0009、ADR-0019、ADR-0021。

管理台使用固定 confidential client moetopia-admin、独立 origin/Cookie/CSRF/application=admin 的 Go RP，复用标准 OIDC 兑换与验证适配。登录强制重新认证，角色在回调、会话创建与管理操作中检查；普通用户或用户站会话不能取得后台权限。自有用户站的既有派生凭据和持久会话保持；登录事务新增客户端绑定，升级中的旧未完成事务重新发起即可。

一次性 CLI 只赋予已有已验证账号初始 administrator 角色，以数据库唯一 bootstrap 行关闭入口。当前不预建多级 RBAC，不开放用户自助提升或任意角色管理。用户已在本次会话指定首位管理员，但不把其真实邮箱写入仓库或固定默认账号。

角色与第一因素成立后仍需 MFA。TOTP 使用锁定的 pquerna/otp v1.5.0，种子 AEAD 加密、最后 counter 防重放；绑定事务另绑定浏览器会话。恢复码为随机高熵值的用途/用户绑定哈希，使用一个即使整组旧码、旧种子及全部管理员会话失效，只返回必须重新绑定的受限会话。完成绑定或验证时旋转 Cookie 和 CSRF，保留原第一因素绝对期限。安全事件和通知与变更同事务；失败验证也提交脱敏审计。全部因素丢失没有在线绕过口，生产应急恢复仍需单独验收。

MFA gate 与审核/暂停、普通账号停启、注册策略、邀请及审计共享外层数据库事务，领域模块只加入、不提前提交。权限校验获得用户/角色/会话锁，变更失败传播到外层回滚；单连接池验证防止领域命令偷偷另开连接。平台暂停与所有者停用分开，所有者不能重新启用绕过；普通用户停启禁止目标为任何管理员主体，避免最后管理员自锁。

增加目标/结果/request ID 的审计字段，不虚构旧事件的缺失内容。列表均有边界和确定顺序；小规模检索不提前引入搜索服务。统计趋势、团队/测试成员、完整角色管理与所有拒绝路径审计尚未交付，不能把这批后台接口描述为完整运营平台。

代价：MFA 与管理命令会持有角色锁直至事务结束，同一管理员操作可能串行；业务事务须保持短小，不放 SMTP/网络调用。新增 Unit 仅用于已存在的跨模块事务参与，不作为通用 repository。未来拆服务需将这个本地事务边界重设计为明确一致性协议，不能机械替换为 RPC。

重新评估条件：第二管理员与角色粒度、长事务/锁等待实测、生产 MFA 时效与通知、全部因素丢失、正式密钥轮换、后台统计、管理员身份的注销/冻结。协议依据：[RFC 6238](https://www.rfc-editor.org/rfc/rfc6238.html)、[OWASP MFA](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html)。
