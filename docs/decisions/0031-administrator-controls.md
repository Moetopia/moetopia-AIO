# ADR-0031：角色控制与限时应急恢复

日期：2026-10-22。状态：在用户已授权的首期范围实施；十五分钟应急期限和控制事务串行为工程基线，不是用户逐项确认的生产政策。

已有 bootstrap/MFA 不能承担持续角色管理，也不能把清空 seed 当作安全恢复。新增当前密码与有效 MFA 保护的角色授予/撤回，使用安全版本作条件写入，必须保留另一名已完成 MFA 的可用管理员。新角色和重新授予均需新登录/绑定，撤回立即清除旧管理凭据并通知目标。

全因素丢失由主机操作员执行显式命令，只对既有启用管理员签发十五分钟单次凭据，不能借此添加角色或绕过密码。数据库仅存 hash；未消费前阻止 enrollment，消费后只授权当前受限会话重新绑定，完成真实 TOTP 后才恢复权限。代价是恢复需要安全保存本次私有文件，丢失受限会话需重新签发。没有引入身份租户、通用 RBAC 或多人审批引擎。

控制事务先锁固定控制行，再排序锁定所有参与身份，协调角色、MFA、审核和账号变更；低流量下接受管理写入串行，普通身份/协议流量不进入该锁。与源代码兼容不代表与旧安全语义兼容：使用新应急状态后不能继续运行忽略它的旧二进制。

唯一契约见 [管理员控制](../run-admin-controls.md)，迁移与实测见 [实施进度](../implementation-status.md)。重新评估条件：多管理角色、更大的管理并发、外部密钥托管、经过验证的双人恢复需要或商业应急政策变化。
