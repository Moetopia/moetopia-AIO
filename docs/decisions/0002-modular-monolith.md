# ADR-0002：模块化单体与多应用工作区

- 状态：架构方向已确认；具体工程和进程安排仍为建议。
- 记录日期：2026-10-17。
- 确认日期：2026-10-17；确认范围为 Go 模块化单体、三个 Nuxt 应用、共享 UI/API 类型与独立部署能力。

## 背景

首期只有身份产品，但之后会加入开放平台及业务模块。直接复刻 nextmoe 的全部服务会提前增加部署和契约负担；完全无边界的单体则容易让业务侵入身份核心。

## 已确认决定

Go 后端采用模块化单体。前端分 account、admin、developer 三个 Nuxt 应用，共享基础 UI 和 API 类型，可分别部署。

具体工程建议：使用 monorepo、pnpm workspace 和一个 Go module；后端按领域拥有数据与接口，首期 API、worker 分进程，前端额外共享翻译资源。上述工具和进程细节不因架构方向确认而自动视为已定案。详见 [架构](../architecture.md)。

## 取舍与替代

三个应用的权限与页面职责清晰，代价是构建和本地启动数量增加。单 Nuxt 应用按路由分区是讨论过但本轮未采用的替代方案；不能在后续实现中自行改回。服务端始终负责后台安全。

微服务留到有独立伸缩、隔离和发布证据后再拆；不因为“可扩展”建立空服务。

## 待验证

三应用 SSR、代理、Cookie 和登录恢复是否简洁；共享包构建是否支持 Windows。模块接口能否避免跨表访问，跨模块事务是否确有必要。

## 重新评估条件

维护人数与发布节奏不足以支撑三个应用，或某个领域出现明确独立资源需求时重新评估。改变应用数不改变共享账号、模块数据所有权和服务端鉴权原则。
