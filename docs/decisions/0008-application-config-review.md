# ADR-0008：已发布应用的敏感配置版本化审核

- 状态：行为方向已确认；细节为建议。
- 记录与确认日期：2026-10-17。
- 确认依据：用户选择“保留旧批准版本，新配置审核后生效”。
- 实施状态：未实施。

## 已确认决定

已发布应用修改回调地址、申请权限或应用身份展示等敏感配置时，生成待审核版本。审核期间旧批准配置继续服务；新配置获批后生效。拒绝或撤回待审配置不改变已批准配置。

## 理由与代价

保持现有应用服务连续，同时让新权限与新回调在生效前接受审核。代价是必须区分当前生效配置与待审配置，并处理并发编辑、审核和版本切换。

直接修改敏感配置后退回测试态是本轮未采用的简化方案，不应在实现中默认使用。

## 细节建议与待验证

- 审核绑定明确配置版本；提交后内容冻结，后续修改生成新版本，不把审批套到未经审阅的内容。
- 批准时检查版本冲突，并原子切换生效配置；协议端点和授权页不得混读新旧字段。
- 审核结果、批准人、版本摘要与生效时间留审计；不在审计保存秘密。
- 平台暂停、所有者紧急停用和凭据撤销建议独立于配置审核，不能因为等待审核而延迟安全动作。
- 生效前已经创建的授权事务、移除 scope 后的旧授权及令牌如何处理，需要随撤销策略定案；不默认永久沿用旧权限。

## 重新评估条件

运营流程或资源成本无法支撑双版本模型时，需要用户重新决定，不能静默改成编辑即停服。细节在实现前通过并发与故障场景验证。
