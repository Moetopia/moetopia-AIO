# ADR-0017：合并用户站与按场景组织页面布局

- 状态：用户已授权实施；视觉继续接受评审。
- 日期：2026-10-18。
- 替代范围：ADR-0002 的三个独立前端决定，以及 ADR-0013/0016 中对应的目录、渲染与默认启动数量；Go 模块化单体及服务端身份边界保留。

## 原因与决定

用户重视 nextmoe 的页面逻辑和布局，同时认为三个前端的维护与启动成本偏高。核对参考源码后，nextmoe 本身确实采用三个 Nuxt 应用，但账号页、认证页、开发者与管理台分别使用不同布局。Moetopia 此前将它们统一为后台工作区，偏离用户期望。

采用两个 Nuxt 应用：`apps/account` 为用户站，包含认证、账号中心与 `/developer` 开发者分区；`apps/admin` 独立。共享 UI、翻译、Nuxt 适配和生成 API 类型继续复用。删除独立 developer 应用的源码与 workspace 入口；开发不再启动 3002，生产不再需要开发者独立域名与构建。

认证页使用独立页壳：桌面左侧表单独立滚动、右侧安静的品牌区域；窄屏只保留可完成任务的表单，不加载候选立绘。账号中心使用轻量顶栏与个人信息摘要/操作内容双栏。开发者首页、说明、应用管理通过真实路由区分，控制台才使用侧栏。管理台维持独立工作区，不把所有场景套进一个后台布局。复用的 AuthShell、ProfileLayout 均在 UI 包维护并提供故事。

## 路径与兼容

| 路径 | 职责 |
| --- | --- |
| `/` | 原有入口；匿名显示登录，已有账号显示资料；带 authorization_request 时继续原授权流程 |
| `/auth/login`、`/auth/register` | 独立登录与注册，切换支持浏览器历史 |
| `/profile`、`/sessions`、`/security` | 资料、登录会话、安全设置 |
| `/developer` | 开发者门户 |
| `/developer/applications`、`/developer/docs` | 应用管理准备状态、接入说明 |

当时的实现保持 account origin、issuer、Go API、授权事务 Cookie 和 CSRF 契约，开发者分区直接使用同源账号状态。2026-10-19 用户要求自有中心也通过 OAuth/OIDC 登录，此路径由 [ADR-0019](0019-first-party-oidc.md) 更新，后端 RP 接入尚未完成。Go 会话所有权及不在浏览器另存令牌的约束不变。管理员权限、重新认证与 MFA 必须继续由 Go 校验；独立前端本身不是权限隔离的证明。私人页面响应禁止共享缓存，静态资源维持独立缓存策略。

旧开发者端口没有部署迁移流量，故不启动一个只为跳转存在的第三进程。若以后已有正式开发者域名，再由入口层定义向用户站路径的兼容跳转，不从未知 Host 推断上游。

## 代价与重新拆分条件

账号与开发者页面共享发布节奏和 SSR 服务；故障影响范围扩大。按路由和业务组件保持职责，新增界面不绕过共享 UI。开发者出现独立团队、发布频率、流量或资源隔离要求时，再评估独立应用；不为未知将来预建部署单元。此次合并不等于实现应用创建、审核、密码恢复或管理员能力。

## 验证边界

执行类型、构建、组件与页面检查，并复核桌面/移动截图。真实数据库与 RP 的协议互操作验证由后端维护的独立运行器完成；本轮页面 mock 不替代真实互操作。最终结果见 [前端协调记录](../coordination/frontend.md)。
